# Directed GRF guard 1 — source only

This is a disabled ABI boundary, **not an implementation of historical football controls**. The Python host is tested with controlled port declarations; no native library has been built, loaded or invoked. See [TP185](../../../../../docs/cases/case_TP185_grf_controlled_adapter_and_native_guard_2026-10-22_01.md).

`manifest.json` pins the base/output bytes for `ai.cpp`, `CMakeLists.txt` and the two new native sources contained in `0001-disabled-directed-abi.patch`. Tests check every hunk in memory against pinned text, without applying a build tree or invoking a compiler. The original audited tree and G2 source profile remain unchanged. The patch retains the existing source notices; see [third-party notices](../../../../../THIRD_PARTY.md).

The proposed build option `TIMEPITCH_DIRECTED_RECONSTRUCTION` defaults to OFF. When selected in a future reviewed build, the patch would add module-level `directed_capabilities_v1` and four instance methods. Metadata declares `native_disabled`, no executable controls/channels and the missing providers. `prepare` refuses incomplete initial-state support; another prepare attempt is refused. `queue`, `step` and `export` refuse rather than forward to action fixtures or ordinary simulation. No world is accessed by these new methods. Evidence fields are null, never fabricated empty native measurements. Source names are not evidence of compiled ABI exports.

The new C++ class has instance-owned refusal state; it does not modify the controller, team AI, ownership, ball, score, clocks, RNG or rendering. Existing support/marking and keeper arbitration therefore receive no directed override. This does **not** prove directed collective play: the legal command path, complete physical initialisation and actual contact/body telemetry still need implementation and validation. Pass recipient/contact/outcome constraints in Python packets are requirements, not verified native effects.

The Python protocol has no native factory or loader. `run_grf_directed` currently permits only an explicitly injected controlled-double mode and returns declaration-only evidence with acceptance:not_assessed. That marker is a host scope restriction, not a security attestation of arbitrary injected Python code. No API or CLI exposes the host. Its bounds (10000 total ticks,1000 commands,100 ticks per call and4MiB per JSON packet) limit controlled work; they are not a new runtime admission or budget. Calls are single-pass; teardown is attempted once on failure and there is no reset/retry/seek.

Missing native initialisation, pass/receiver/shot/header/save/block/recovery/interception/duel control, continuous contact/body evidence, source-equivalent artifact and fractional-time support remain explicit gaps. The [time/contact proposal](../../../../../docs/superpowers/specs/2026-10-22-grf-directed-time-contact-design.md) is still unapproved. Native source preparation/compilation requires separate selection after patch review; controlled test success does not grant it. No post-build probe, engine import or saved-play execution is authorized here.
