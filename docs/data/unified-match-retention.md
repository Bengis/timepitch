## Loading and contract gates

- Historical source identity is checked using active capabilities, match ID, dataset/reconstruction identity, event-page identity and exact statistics cutoff. A source response for a previous session/destination cannot publish.
- `ensure` / `loadPanel` accept optional explicit demand context. Playing uses five-second statistics cutoffs; paused/explicit seek uses the exact source cursor. Never infer user intent from timing.
- `ReadPool` joins identical reads and reserves LRU space before another decoded payload. Three segments maximum,4MiB each /12MiB total payload. Previous poses use an available cached interval; otherwise the hook marks a restart rather than blocking a new destination on an older read. Changing windows aborts obsolete consumers.
- Event windows are ≤60seconds; pagination has a12MiB cumulative limit and must finish without abort/identity change before publishing.100same-window notifications cause one segment/event read. Explicit new-window demand deduplicates under the same identity.
- One statistics transport at a time, ≥250real ms between starts, latest pending panel demand coalesced. Retain a completed cutoff only if it is not ahead of the cursor. Manual retry clears failed-read latches; no automatic tight retry loop.120×real-elapsed test exercises crossing windows under these bounds.
- A fact inside two coordinate samples splits the **fact validity interval**, preserving the original raw interpolation time domain. This avoids re-timing motion or pre-interpolating in the adapter. The next interval owns exact right-boundary facts; final point markers remain valid.
- Raw final data is explicitly separated (`finalDetails` / descriptor finalResult / final-scope panels). A phase3 presenter must not dump those objects into the cursor Data tab before reveal. Synthetic tracking never supplies historical possession/effort metrics.
- Adapters contain no JSX/screen component, RAF/controller, native/model creation or second lerp implementation. `StatisticsQueue` uses a bounded I/O scheduling timeout, not a playback timer. Existing live entries remain unchanged through phase3.
